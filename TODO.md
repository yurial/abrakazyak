## Решения, согласованные с заказчиком

1. Режим первой версии — офлайн: один телефон передаётся по кругу; онлайн-режим заявлен в планах (plan.md, стадия 3).
2. Завершение партии — написанная концовка или выбор шаблона из списка (game R3.2, R3.3).
3. Имена участников опциональны; авторство при чтении показывается, только если имена введены (game R1.3, ui R7.2).
4. Готовый рассказ: экран чтения, системный диалог «Поделиться», локальный архив с перечитыванием (ui R7, ui R8, storage R2).
5. Текущая партия автосохраняется; при запуске предлагается продолжение с места остановки (storage R1, ui R3).
6. Мультиязычная архитектура с расширением на любой язык; первая версия — русский и английский (ui R9).
7. Круги (раунды): число кругов задаётся на экране участников до старта, минимум — один круг; по умолчанию предлагается вычисляемое `defaultRoundCount` — наибольшее из единицы и округления вверх `minimumPlannedReplies` / число участников, что гарантирует не менее `minimumPlannedReplies` текстов в рассказе; последний ход партии — ход завершения последнего участника (game R1.7–R1.11, ui R2.4, R2.5).
8. Досрочное завершение доступно на обоих экранах ввода: `screen-chunk` и `screen-tail` (game R3.6–R3.8, ui R4.7, R5.6).
9. Вход в архив с первого экрана `screen-rules` (ui R1.3).
10. Сборка рассказа: каждая реплика и концовка печатаются с новой строки, авторство привязывается к строкам (game R4.1, R4.3).
11. Правила доступны в любой момент из любого игрового экрана с возвратом без потери состояния (ui R10).

## Принятые без явного согласования — подтвердить

12. Лимиты `maxStoryChunkLength` и `maxVisibleTailLength` считаются в символах с пробелами и жёстко ограничивают ввод (game R2.4–R2.7).
13. Правка своего текста доступна до нажатия кнопки подтверждения; после подтверждения текст зафиксирован (ui R4.6, R5.5).
14. Жёсткого максимума игроков нет; рекомендация «до `recommendedMaxPlayers` человек» и значение `recommendedMaxPlayers` предложены исполнителем спецификаций и требуют подтверждения заказчика (game R1.1, R1.2).
15. Кнопки подтверждения неактивны при пустом или содержащем только пробелы вводе (ui R4.5, R5.4, R6.7).
16. На экранах ввода отображается счётчик оставшихся символов (ui R4.4, R5.3, R6.6).
17. При выборе «Играть» партия начинается сразу; имена — опциональный экран участников, который можно пропустить, не вводя имена (ui R2.1–R2.3).
18. Окно валидности досрочного завершения: после `submitTail` (после передачи хода) завершение переданного хода невозможно — код `game/invalid-step`. Правило предложено исполнителем спецификаций; заказчик видел формулировку, но явно не выбрал её — требует подтверждения (game R3.1, R3.6; ui R4.7, R5.6).
19. `startMatch` с пустым списком участников отклоняется кодом `game/empty-participants`; недопустимое число кругов — кодом `game/invalid-round-count` (game R1.6, R1.7).
20. Партия технически допускает и одного участника; минимума «два игрока» модель не навязывает (game R1.1).
21. Экран участников — строки с добавлением и удалением (минимум одна строка остаётся), имя в строке необязательно (ui R2.2).
22. Завершение инициируется кнопкой на экране ввода через отдельный экран завершения с двумя вариантами; возврат к обычному ходу возможен (ui R4.7, R6.1, R6.5).
23. При уходе на `screen-finish` и возврате набранный неподтверждённый текст сохраняется (ui R6.9).
24. Экран `screen-finish` отображает видимый хвост предыдущего участника (ui R6.8).
25. Завершение партии удаляет черновик; отказ от продолжения при запуске также удаляет черновик (storage R1.3, R1.4; ui R3.2).
26. Повреждённый черновик трактуется как отсутствующий и не препятствует новой партии (storage R1.5).
27. Архивная запись содержит дату и время завершения; порядок архива — от новых к старым; из архива доступен возврат к экрану вызова (storage R2.1, R2.2; ui R8.3).
28. Правила в любой момент реализованы диалогом `dialog-rules` с явным возвратом; на `screen-rules` отдельная кнопка не нужна (ui R10).
29. Язык интерфейса следует системному языку устройства; резервный язык — русский `fallbackLanguage` (ui R9.4).
30. Тексты шаблонных концовок остаются в конфигурации `game` (`templateEndingsByLanguage`), паритет с `uiLanguages` обеспечивается требованием ui R9.5 (см. Justification в `ui`).
31. Английские формулировки текстов интерфейса и шаблонных концовок — предварительные, требуют вычитки носителем языка (ui Interface, game Configuration).
32. Вход в архив — с `screen-rules`, `screen-names` и `screen-story`; с экранов ввода хода (`screen-chunk`, `screen-tail`, `screen-finish`) архив сознательно не открывается, чтобы не уводить телефон из цикла передачи; при продолжении прерванной партии архив становится доступен после завершения партии — подтвердить допустимость (ui R1.3, R2.8, R7.4, J5). Все три входа реализованы в приложении; кнопка `rules.archive` на `screen-names` добавлена по итогам независимой сверки.
33. Предложение числа кругов на `screen-names`: предзаполнение вычисляется при открытии экрана и пересчитывается при изменении числа строк участников, пока поле не отредактировано вручную; после ручной правки значение сохраняется и пересчётом не затирается — поведение зафиксировано по предписанию контрольного ревью, требует подтверждения заказчика (ui R2.6, R2.7).
34. Фон `dialog-resume` — экран `screen-rules`; диалог модален и блокирует остальные действия до выбора продолжения или отказа — поведение предложено исполнителем, требует подтверждения заказчика (ui R3.3).
35. Чтение архивной записи переиспользует экран `screen-story` без отдельного экрана просмотра — наименее затратный вариант по итогам независимой проверки, требует подтверждения заказчика (ui R8.2).

## Решения реализации фазы B (модуль :core) — подтвердить

36. Ошибки `game/*` и `storage/entry-not-found` передаются типом результата (sealed-иерархии `GameResult`/`StorageResult` с кодами спецификации), а не исключениями; сбои файловой системы (`IOException`) пробрасываются как прежде и задокументированы в контрактах операций хранилища (game Error handling, storage Interface).
37. «Нецелое» число кругов (game R1.7) в типизированном Kotlin API непредставимо: параметр `startMatch` имеет тип `Int?`, поэтому отклоняется только значение менее единицы (`game/invalid-round-count`); проверка пустоты списка участников выполняется до проверки числа кругов.
38. Окно завершения (game R3.6) реализовано через проверку актуальности состояния: операции принимают последнее возвращённое состояние партии, а операция с ранее снятым состоянием (ход уже передан либо внутри хода подтверждён другой шаг) отклоняется `game/invalid-step`; идентификаторы шаблонных концовок построены как `ru-1…ru-3` / `en-1…en-3`, уникальны между языками, `finishWithTemplate` проверяет идентификатор против объединённого списка всех языков (game R3.3).
39. Концовка готового рассказа несёт авторство участника, выполнившего ход завершения (game R4.3 требует авторство только для реплик; расширение принято исполнителем — полезно для экрана чтения и архива).
40. Единица длины текста — `String.length` (кодовые единицы UTF-16), включая пробелы (game R2.4, R2.6); символ за пределами базовой многоязычной плоскости (эмодзи) считается за две единицы; спецификация единицу символа не уточняет.
41. Повреждённый файл архива трактуется как пустой архив (следующая запись пересоздаёт файл); спецификация (storage) определяет поведение только для повреждённого черновика (R1.5) — для архива поведение выбрано исполнителем.
42. Идентификаторы записей архива — `entry-N` по порядку добавления; записи с равным моментом завершения упорядочиваются по времени добавления — более поздняя выше (storage R2.2).
43. Автосохранение после каждого подтверждённого шага и удаление черновика при завершении партии (storage R1.1, R1.3) — обязанность вызывающей стороны (фаза C UI): `saveDraft` вызывается после каждого подтверждённого шага, `clearDraft` — после `finishWithReply`/`finishWithTemplate`; на уровне `:core` контракт операций обеспечен, сам «автоматизм» принадлежит экранам.

## Решения реализации фазы C (модуль :app) — подтвердить

44. Роутинг — state-based на чистых JVM-ViewModel (`AppUiState.screen` + производный по фазе хода экран сессии); navigation-compose не используется: все решения навигации (R1–R10) покрыты юнит-тестами ViewModel, дерево экранов линейно.
45. ViewModels — чистые JVM-классы на `StateFlow` без Android-зависимостей; удержание состояния при пересоздании Activity — через `onRetainCustomNonConfigurationInstance` (deprecated-пара API Activity), чтобы не заводить зависимость от androidx.lifecycle в ViewModel-логике; при смене локали язык концовок пересчитывается в `updateLanguage`.
46. Число строк участников на `screen-names` по умолчанию — 2: спецификация не задаёт значение (Открытые вопросы, п. 6); выбрано по аудитории «два и более человек».
47. Ввод сверх лимита отклоняется целиком (текст не изменяется), а не обрезается до лимита — интерпретация «превышающий лимит ввод не принимается» (ui R4.3, R5.2, R6.2); пустая строка отвергается кнопками подтверждения (неактивны при отсутствии непробельного символа).
48. Авторство строки рассказа отображается отдельной строкой «— Имя» под текстом реплики, только если имя задано (ui R7.2); формат — решение реализации, спека форму не задаёт.
49. Дата и время записи архива печатаются в системной зоне локализованным форматом устройства; сортировка записей — из хранилища (storage R2.2).
50. Storage I/O (черновик, архив) выполняется на главном потоке: объёмы — микрофайлы, режим офлайн; при заметном росте архива потребуется фоновая загрузка списка.
51. java.nio.file и java.time из `:core` исполняются на minSdk 24 через core library desugaring — артефакт `desugar_jdk_libs_nio` 2.x (уточнено после краша v0.1.0, см. п. 56: java.nio.file покрывает только `_nio`-конфигурация, дефолтный `desugar_jdk_libs` — никогда, ни в одной версии). Точечное подавление lint `NewApi` на `AppContainer` снято: с nio-конфигурацией lint видит покрытие `File#toPath`/`Path#resolve` по своей базе desugared-API и NewApi не возникает (прогон lintDebug — 0 ошибок).
52. Лимит числа участников при старте не ограничивается в UI; рекомендация «до 10 человек» звучит только в правилах (game R1.1, R1.2, ui R1.2).
53. Возврат с экрана завершения на прерванный ход (ui R6.5) — кнопкой `rules.back` и системным back; на ходе завершения (game/finishing-turn) оба отключены — возврата нет.
54. Непокрытое автотестами (честно): рендеринг и переходы Composable-экранов и диалогов, системный «Поделиться» (ACTION_SEND), BackHandler-wiring, adaptive-иконка, реальная персистентность файлов в Android-окружении. Поведенческие сценарии закреплены юнит-тестами ViewModel (79 тестов: `AppViewModelTest` — навигация R1–R10, `MatchViewModelTest` — ввод/автосохранение/завершение, `NamesViewModelTest` — R2, `StringsCatalogTest` — R9.2 и дословность RU и EN, `TemplateParityTest` — R9.5). Robolectric/Compose-тесты не добавлялись: затраты на стабилизацию против добавляемой ценности при thin-UI над покрытой логикой.
55. Новый lint-ворнинг `PluralsCandidate` (англ. `rules_body`: «%1$d people»): текст зафиксирован таблицей Interface specs/ui.md дословно, plural-ресурс противоречил бы составу каталога; существующие 3 ворнинга каркаса не изменялись, `MissingApplicationIcon` устранён.
56. Root cause краша релиза v0.1.0 «после ввода имён участников — кнопка „Начать игру“ падает»: файловые хранилища `:core` исполняют java.nio.file (`Files.writeString/readString` и прочие), а core library desugaring был подключён дефолтным артефактом `desugar_jdk_libs:2.1.5`, который java.nio.file не десугарит — в его конфигурации (`desugar_jdk_libs_configuration`) и lint-базе нет ни одного класса `java/nio/file`. Первый же `saveDraft` (NamesScreen → `confirmNames` → `startNewMatch`) бросал `NoSuchMethodError`: `Files.writeString` отсутствует в Android на всех уровнях API (проверено по платформе android-36), а сами классы java.nio.file появились в платформе только с API 26 — на API 24–25 приложение падало ещё при запуске, на `File#toPath` в `AppContainer`. JVM-тесты и Robolectric дефект не ловят (java.nio.file берётся из JDK), lint не видел его из-за точечного подавления NewApi (бывший п. 51) и потому, что использования живут в `:core` — чистом JVM-модуле вне Android-lint. Исправлено переключением артефакта на `desugar_jdk_libs_nio:2.1.5` (покрыт каждый используемый API; в dex-выходе ссылки переписаны в `j$/nio/file`). Регрессия закрыта `DesugaringConformanceTest` (таблица используемых API + скан продакшн-исходников против lint-базы активной конфигурации; срабатывает и на JVM — на дефолтной конфигурации тест красный) и guard-ом wiring-а в `app/build.gradle.kts` (сборка падает при замене артефакта). Проверено прогоном `:core:test :core:koverVerify :app:testDebugUnitTest :app:lintDebug` — всё зелёное; фактический запуск на устройстве/эмуляторе остаётся за заказчиком (в среде исполнения эмулятора нет).
