# Интерфейс «Abrakazyak»

Status: draft
Spec source of truth for: экраны мобильного приложения «Abrakazyak» (Android и iPhone), тексты интерфейса, поведение ввода, навигация и локализация

## Overview

Спецификация определяет экраны приложения, их содержимое и переходы, каталог текстов интерфейса на русском и английском языках и подход к локализации. Игровые правила и модель партии определены в `game`, хранение — в `storage`. Приложение работает офлайн: один телефон передаётся по кругу.

## Scope

**In:** экраны приложения (правила, участники, ввод реплики, ввод хвоста, завершение, чтение рассказа, архив, возобновление партии); каталог текстов интерфейса; поведение ввода (лимиты, счётчик символов, активность кнопок); навигация; локализация и расширение на новые языки.

**Out (non-goals):** правила игры и модель партии (`game`); хранение черновика и архива (`storage`); сетевой режим; ручная настройка языка внутри приложения (первая версия); графический дизайн, анимации и платформенные детали, не влияющие на поведение экранов.

## Interface

Экраны приложения:

- `screen-rules` — первый экран: описание правил и кнопка «Играть».
- `screen-names` — старт партии: список участников с необязательными именами.
- `screen-chunk` — ввод реплики текущего хода.
- `screen-tail` — ввод видимого хвоста для следующего участника.
- `screen-finish` — завершение партии: финальная реплика или шаблонная концовка.
- `screen-story` — чтение готового рассказа.
- `screen-archive` — список архивных рассказов.
- `dialog-resume` — предложение продолжить прерванную партию.

## Configuration

- `uiLanguages`: список строк; `ru`, `en`; fixed; языки интерфейса первой версии; связана с R9.1, R9.2, R9.4.
- `fallbackLanguage`: строка; `ru`; fixed; язык интерфейса, если системный язык устройства не входит в `uiLanguages`; связана с R9.4.

## Requirements

- R1. Первый экран и правила:
- R1.1. verification=manual; При запуске без черновика приложение открывает `screen-rules` с описанием правил и кнопкой `rules.play`.
- R1.2. verification=manual; Экран `screen-rules` отображает игровые правила из `game`, включая рекомендацию числа участников и способ передачи устройства по кругу.
- R2. Старт партии:
- R2.1. verification=manual; Нажатие `rules.play` ведёт на `screen-names` — старт партии с опциональными именами участников.
- R2.2. verification=manual; Экран `screen-names` позволяет добавлять и удалять строки участников, при этом хотя бы одна строка участника всегда присутствует.
- R2.3. verification=scenario; Подтверждение старта создаёт партию из участников, представленных строками на момент подтверждения, и открывает первый ход на `screen-chunk`.
- R3. Возобновление партии:
- R3.1. verification=scenario; При запуске с сохранённым черновиком незавершённой партии приложение показывает `dialog-resume`, и согласие открывает экран текущего хода с восстановленным состоянием партии.
- R3.2. verification=scenario; Отказ от продолжения в `dialog-resume` открывает старт новой партии на `screen-names`, и прежний черновик удаляется.
- R4. Ввод реплики (`screen-chunk`):
- R4.1. verification=manual; На первом ходе экран показывает `chunk.title.first`, на последующих ходах — `chunk.title.next`.
- R4.2. verification=scenario; На каждом ходе после первого экран отображает `game/visible-tail` предыдущего участника и не отображает другие тексты партии.
- R4.3. verification=manual; Поле ввода реплики ограничено `maxStoryChunkLength` символами, и превышающий лимит ввод не принимается.
- R4.4. verification=scenario; Во время ввода отображается счётчик оставшихся символов `chunk.counter`.
- R4.5. verification=scenario; Кнопка `chunk.done` неактивна, пока введённый текст не содержит ни одного непробельного символа.
- R4.6. verification=manual; Введённый текст реплики можно править до нажатия `chunk.done`; после подтверждения реплика зафиксирована и не редактируется.
- R4.7. verification=manual; На `screen-chunk` доступна кнопка `chunk.finish`, ведущая на `screen-finish` для завершения партии.
- R5. Ввод хвоста (`screen-tail`):
- R5.1. verification=manual; Экран `screen-tail` показывает `tail.title` и поле ввода видимого хвоста.
- R5.2. verification=manual; Поле ввода хвоста ограничено `maxVisibleTailLength` символами, и превышающий лимит ввод не принимается.
- R5.3. verification=scenario; Во время ввода отображается счётчик оставшихся символов `tail.counter`.
- R5.4. verification=scenario; Кнопка `tail.done` неактивна, пока введённый текст не содержит ни одного непробельного символа.
- R5.5. verification=manual; Введённый текст хвоста можно править до нажатия `tail.done`; после подтверждения ход передаётся следующему участнику, и открывается `screen-chunk` следующего хода.
- R6. Завершение партии (`screen-finish`):
- R6.1. verification=manual; Экран `screen-finish` предлагает два способа завершения: написать `game/final-reply` или выбрать `game/template-ending`.
- R6.2. verification=manual; Ввод `game/final-reply` ограничен `maxStoryChunkLength` символами, снабжён счётчиком оставшихся символов и кнопкой завершения, неактивной при отсутствии непробельного символа.
- R6.3. verification=manual; Список шаблонных концовок отображается текстами из `templateEndingsByLanguage` для текущего языка интерфейса.
- R6.4. verification=scenario; Выбор `game/template-ending` немедленно завершает партию без ввода финальной реплики.
- R6.5. verification=manual; Экран `screen-finish` позволяет вернуться к прерванному обычному ходу без завершения партии.
- R7. Чтение рассказа (`screen-story`):
- R7.1. verification=scenario; Сразу после завершения партии приложение открывает `screen-story` с полным текстом `game/finished-story`.
- R7.2. verification=manual; Авторство реплик отображается на `screen-story` только для участников с заданными именами.
- R7.3. verification=manual; Кнопка `story.share` открывает системный диалог «Поделиться» с полным текстом рассказа.
- R7.4. verification=manual; С `screen-story` доступны переходы `story.play-again` (новая партия через `screen-names`) и `story.archive` (открытие `screen-archive`).
- R8. Архив (`screen-archive`):
- R8.1. verification=scenario; Экран `screen-archive` показывает записи архива в порядке от новых к старым.
- R8.2. verification=scenario; Выбор записи архива открывает её полный текст с авторством по правилам R7.2.
- R9. Локализация:
- R9.1. verification=manual; Все тексты интерфейса оформлены как `ui/string-resource`, и первая версия поставляется с наборами для всех языков из `uiLanguages`.
- R9.2. verification=automated; Наборы `ui/string-resource` всех языков из `uiLanguages` содержат одинаковые множества ключей.
- R9.3. verification=manual; Добавление нового языка не изменяет поведение приложения и сводится к добавлению набора `ui/string-resource` с теми же ключами.
- R9.4. verification=manual; Язык интерфейса следует системному языку устройства; при неподдерживаемом системном языке используется `fallbackLanguage`.

## Usage constraints

- Целевые платформы — Android и iPhone; поведение экранов описано платформенно-независимо.
- Все тексты пользователь видит на языке интерфейса, выбранном по R9.4.
- Требования к графическому дизайну, анимациям и доступности не входят в эту спецификацию и фиксируются при реализации.

## Justification

- J1. Поток экранов повторяет согласованный с заказчиком сценарий «правила — участники — реплика — хвост — чтение» (R1–R7) и сохраняет минимальное число шагов при передаче телефона по кругу.
- J2. Кнопки, неактивные при пустом вводе (R4.5, R5.4), и счётчики символов (R4.4, R5.3) предотвращают ошибки ввода до подтверждения, когда правка уже невозможна (R4.6, R5.5).
- J3. Каталог `ui/string-resource` и правило одинаковых ключей (R9.2, конфигурация `uiLanguages`) делают добавление языка (R9.3) механической работой без изменения поведения.

## Error handling

Ошибки модели `game` (`game/empty-text`, `game/text-too-long` и остальные коды из спецификации `game`) не показываются игроку: интерфейс предотвращает их возникновение ограничением поля ввода (R4.3, R5.2, R6.2), счётчиком и неактивными кнопками (R4.4, R4.5, R5.3, R5.4).

## Dependencies

- `game` — экраны отображают правила, лимиты текста, шаблонные концовки и сущности модели партии.
- `storage` — возобновление партии и архив используют операции хранилища.

## Used by

Отсутствуют: `ui` — листовая спецификация приложения, другими спецификациями не используется.
