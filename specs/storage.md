# Локальное хранение «Abrakazyak»

Status: draft
Spec source of truth for: локальное хранение игры «Abrakazyak» — черновик текущей партии и архив завершённых рассказов

## Overview

Спецификация определяет локальное хранение на устройстве: автоматическое сохранение состояния текущей партии (`storage/draft`) с восстановлением после перезапуска и архив завершённых рассказов (`storage/archive`). Партии и рассказы соответствуют модели, определённой в `game`. Экраны и взаимодействие с пользователем — область спецификации `ui`.

## Scope

**In:** сохранение и восстановление черновика текущей партии; автосохранение; удаление черновика; пополнение и чтение архива завершённых рассказов; поведение при повреждённых данных.

**Out (non-goals):** экраны и взаимодействие с пользователем (`ui`); правила игры и модель партии (`game`); сетевой режим и облачная синхронизация; удаление и редактирование записей архива (не запрошено заказчиком, см. TODO.md); экспорт архива; ограничения объёма хранилища.

## Interface

Операции хранилища (контракт для `ui`; сигнатуры концептуальные, без привязки к коду):

- `saveDraft(state)` — сохраняет полное состояние незавершённой партии; вызывается автоматически после каждого подтверждённого шага партии.
- `loadDraft()` — возвращает сохранённое состояние партии либо признак «отсутствует».
- `clearDraft()` — удаляет черновик.
- `addFinishedStory(story)` — добавляет завершённый рассказ в архив и возвращает идентификатор записи.
- `listArchiveEntries()` — возвращает список записей архива, упорядоченный от новых к старым.
- `readArchiveEntry(entryId)` — возвращает запись архива по идентификатору.

Коды ошибок (полный список):

- `storage/entry-not-found` — `readArchiveEntry` с неизвестным идентификатором.
- Повреждённый черновик не возвращает код ошибки: `loadDraft` сообщает «отсутствует» (см. R1.5).

## Requirements

- R1. Черновик текущей партии:
- R1.1. verification=automated; Состояние незавершённой партии автоматически сохраняется локально после каждого подтверждённого шага партии без действия пользователя.
- R1.2. verification=automated; Сохранённый черновик восстанавливает состояние партии до последнего подтверждённого шага, включая список и порядок участников, число кругов, текущий ход (`game/turn`), видимый контекст (`game/visible-context`) текущего хода и все написанные тексты.
- R1.3. verification=automated; Завершение партии удаляет сохранённый черновик.
- R1.4. verification=automated; Старт новой партии заменяет сохранённый черновик состоянием новой партии.
- R1.5. verification=automated; Нечитаемый черновик трактуется как отсутствующий и не препятствует старту новой партии.
- R1.6. verification=automated; Набранный, но не подтверждённый текст шага не входит в черновик и при перезапуске приложения теряется.
- R2. Архив завершённых рассказов:
- R2.1. verification=automated; Каждая завершённая партия автоматически попадает в архив в виде `storage/archive-entry` с полным текстом `game/finished-story`, авторством реплик при наличии имён участников и датой и временем завершения.
- R2.2. verification=automated; Записи архива упорядочиваются по дате и времени завершения от новых к старым.
- R2.3. verification=automated; Запись архива остаётся доступной для чтения после перезапуска приложения.

## Examples

- E1. Примеры черновика:
- E1.1. Участник подтвердил реплику — хранилище сохранило состояние; приложение закрыли посреди следующего хода — при запуске партия продолжилась с места остановки.
- E1.5. Файл черновика оказался повреждён — приложение ведёт себя как при отсутствии черновика и предлагает только новую игру.
- E1.6. Игрок набрал реплику, но не нажал кнопку подтверждения; после перезапуска поле ввода пусто, а партия продолжилась с последнего подтверждённого шага.
- E2. Примеры архива:
- E2.1. Вечером компания сыграла три партии; каждая появилась в архиве с текстом, временем завершения и именами, а утром все три рассказа открылись заново.

## Usage constraints

- Хранение локальное, на устройстве; работа не требует сети.
- Хранилище должно допускать будущий сетевой режим: формат состояния партии не привязан к одному устройству жёстче, чем требует офлайн-режим (рекомендация заказчика для дизайна состояния, не требование публичного поведения).
- Объём архива и срок хранения записей в первой версии не ограничиваются.

## Justification

- J1. Автосохранение после каждого шага (R1.1) исключает потерю партии при внезапном закрытии приложения: телефон передаётся по кругу, и риск прерывания высок.
- J2. Автоматическое пополнение архива (R2.1) выполняет согласованное с заказчиком требование перечитывать сыгранные истории без лишних действий игрока.
- J3. Трактовка повреждённого черновика как отсутствующего (R1.5) сохраняет запуск приложения работоспособным: черновик — восстанавливаемая данными игра, а не критические данные пользователя.

## Error handling

- `storage/entry-not-found` — чтение записи архива с неизвестным идентификатором; состояние архива при этом не изменяется.
- Повреждённый черновик не является ошибкой для вызывающей стороны: `loadDraft` возвращает «отсутствует» (R1.5), и приложение продолжает работу.

## Dependencies

- `game` — хранилище сохраняет и возвращает сущности модели партии (`game/match`, `game/round`, `game/step`, `game/turn`, `game/story-chunk`, `game/visible-tail`, `game/visible-context`, `game/finished-story`) и опирается на её ограничения валидности.

## Used by

- `ui` — экраны возобновления партии и архива используют операции `loadDraft`, `clearDraft`, `addFinishedStory`, `listArchiveEntries`, `readArchiveEntry`.
